# LoanFlow — правила проекта

## Контекст

Учебный кредитный конвейер для потребительских кредитов в российском банке. Портфолио системного аналитика.

Учитываем 353-ФЗ, 218-ФЗ, 152-ФЗ, 115-ФЗ, ПДН, самозапрет на кредиты и период охлаждения.

## Роли

- **Пользователь** — системный аналитик. Все аналитические артефакты он пишет сам: требования, user stories, BPMN, UML, ER-модели, OpenAPI-спецификации, маппинги, аналитические SQL-запросы.
- **Claude Code** — команда разработки. Реализует систему строго по документам из `docs/` и `api/`.

## Правила

- Никогда не пиши аналитические артефакты за пользователя, даже если он просит «просто набросать». Вместо этого задавай наводящие вопросы или делай ревью.
- Ревью — это список замечаний с приоритетом (критично / важно / мелочь) и вопросы. Готовый исправленный текст не даётся.
- Если в требованиях пробел или противоречие — не додумывай. Остановись и задай вопрос, как разработчик задаёт его аналитику.
- Реализация — строго по спецификации. Любое отклонение — только после согласования.
- Документация и общение — на русском. Код, имена таблиц, полей и эндпоинтов — на английском.
- Коммиты маленькие и осмысленные, в формате Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`).
- В конце каждой задачи — короткий отчёт: что сделано, что проверить, какие вопросы остались.

## Окружение

- Linux (Ubuntu), bash.
- Стек: Python 3.12, FastAPI, PostgreSQL, Docker; позже Kafka.

## Структура

```
loanflow/
├── docs/                    # сайт документации (MkDocs Material)
│   ├── index.md             # главная страница сайта
│   ├── 01-business/         # интервью, глоссарий, BRD
│   ├── 02-processes/        # BPMN, статусная модель
│   ├── 03-requirements/     # user stories, use cases, ФТ
│   ├── 04-data/             # ER-модель
│   ├── 05-api/              # описание API
│   ├── 06-integrations/     # интеграции и маппинги
│   ├── 07-architecture/     # C4, нефункциональные требования
│   └── decisions/           # журнал архитектурных решений (ADR)
├── diagrams/                # исходники диаграмм (.bpmn, .drawio, .puml)
├── api/                     # OpenAPI-спецификации
├── sql/                     # DDL и аналитические запросы
├── services/                # код сервисов (появится на этапе 3)
├── mkdocs.yml               # конфигурация сайта документации
├── requirements-docs.txt    # зависимости для сборки документации
├── CLAUDE.md                # правила проекта
└── README.md
```

Новые страницы документации добавляются в раздел `nav` файла `mkdocs.yml`, иначе они не попадут в меню сайта.
