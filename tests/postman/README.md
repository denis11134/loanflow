# 3.4. Приёмка LoanFlow в Postman

Ожидаемые HTTP-статусы и коды взяты из [OpenAPI](../../api/loanflow.openapi.yaml).
Сценарии [задачи №17](https://github.com/denis11134/loanflow/issues/17) сверены с
[требованиями 1.6](../../docs/03-requirements/1.6-mvp-requirements.md),
[главой 3.3](../../docs/03-requirements/3.3-calculation-tasks.md) и
[HTTP-тестами LoanFlow](../test_service.py) и [АБС](../test_service_abs.py).

## Полный прогон

Нужны Python с зависимостями из `requirements-checks.txt`, серверные утилиты PostgreSQL 18,
`fonts-dejavu-core`, `poppler-utils`, Node.js и Newman 6.2.2 (`npm install -g newman@6.2.2`).
Из корня репозитория под обычным пользователем выполните:

```bash
PYTHONPATH="$PWD:$PWD/tests" .venv/bin/python tests/postman/stand.py
```

Если утилиты PostgreSQL 18 установлены отдельно, задайте `PG_BINDIR=/usr/lib/postgresql/18/bin`.
Если Newman установлен вне `PATH`, добавьте `--newman /путь/к/newman`.
Скрипт поднимает пустой временный PostgreSQL, применяет миграции, запускает API, учебную АБС
и воркер, генерирует локальные токены и запускает Newman. Затем он проверяет содержимое PDF
и внутренние эффекты в базе. При сбое команда возвращает ненулевой код.

Чтобы повторить прогон, выполните ту же команду. Каждый запуск создаёт новый стенд
на свободных локальных портах. По завершении временная база и файл окружения удаляются.
Коллекция передаёт ID и ключи между запросами. Опрос фоновых операций ограничен 20 секундами
на шаг, таймаут отдельного HTTP-запроса в Newman составляет 5 секунд.

## Что требует подготовки

| Сценарий | Что готовит `stand.py` |
|---|---|
| Автоматическая выдача | Сумма 49 999,99 ₽ проходит без охлаждения. Тестовый воркер использует сгенерированный учебный SMS-код. В АБС включается `AUTO_POST` для созданного распоряжения. |
| Чужая заявка и ручная ветка | Второй клиент со своим токеном и оператор с ролью андеррайтера. Заявка на 37 месяцев попадает в `UNDERWRITING` и проходит до публикации ИУ после ручного решения. |
| Бизнес-отказ и ошибка оценки | Два профиля с доходом `null`. Поле текущих платежей есть для `BANK_REJECTED` и отсутствует для `SYSTEM_ERROR`. |
| ПДН 50% и 50,01% | При доходе 100 000 ₽ текущие платежи равны 45 368,27 ₽ и 45 378,27 ₽. Регулярный платёж по новому кредиту равен 4 631,73 ₽. |
| ПСК 24,99%, 25,00%, 25,01% | Для трёх выделенных клиентов тестовый воркер подставляет однопериодные потоки из 3.3. LoanFlow рассчитывает ПСК и проверяет допуск. При 25,01% проверка БД подтверждает `PSK_LIMIT_EXCEEDED` и отсутствие резерва и ИУ. |
| Округление в PDF | Штатный график на 1 600 ₽ и один месяц даёт `20.002500000000` в JSON. Текст фактически полученного PDF содержит `20.003%`. |

## Запуск из Postman Desktop

```bash
PYTHONPATH="$PWD:$PWD/tests" .venv/bin/python tests/postman/stand.py --postman
```

Импортируйте [коллекцию](loanflow.postman_collection.json) и временное окружение по пути,
который выведет команда. [Шаблон окружения](local.postman_environment.json) хранится без токенов
и SMS-кода. Выберите временное окружение и запустите всю коллекцию через **Run collection**.
Для нового прогона остановите стенд через Ctrl+C, запустите его заново и импортируйте новое окружение.

При запуске только через Postman вручную сохраните PDF из папок «ПДН 50%» и «Округление ПСК в PDF».
Сверьте регулярный платёж 4 631,73 ₽ и ПСК `20.003%` соответственно. Внутренние коды, отсутствие
снимка и задания у черновика, отсутствие дублей и состояния резервов проверяет полный прогон
через `stand.py`. Он также извлекает текст PDF через `pdftotext` и сверяет SHA-256 с предложением.

## Результат приёмки

На чистом стенде Newman 6.2.2 выполнил 77 HTTP-запросов с учётом опроса и 172 проверки без ошибок.
PDF подтвердили регулярный платёж 4 631,73 ₽ и округление ПСК до `20.003%`.
Повторный прогон на чистом стенде также прошёл без ошибок. Глава 3.4 принята.

Фактический показ текста предупреждения проверяется в интерфейсе МП. Коллекция проверяет ответ API
и отправляет подтверждение показа от имени МП.
