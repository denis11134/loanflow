# Контракт учебной АБС

Контракт фиксирует операции и гарантии АБС для учебного стенда LoanFlow. Порядок отправки, ручной сверки и учёта резерва МПЛ описан в [статусной модели v3](../02-processes/1.5-status-model.md).

## Отправка распоряжения

LoanFlow передаёт распоряжение с неизменяемым `instruction_id`. Повтор с тем же идентификатором и теми же реквизитами возвращает состояние исходного распоряжения. Запрос с тем же идентификатором и изменёнными реквизитами отклоняется. На один `instruction_id` приходится максимум одна проводка.

## Чтение состояния

АБС возвращает состояние по `instruction_id`.

| Состояние | Значение |
|---|---|
| `NOT_FOUND` | АБС не нашла записи по идентификатору. Результат может измениться при поздней доставке распоряжения. |
| `PENDING` | Распоряжение принято в обработку. Итог зачисления ещё неизвестен. |
| `POSTED` | Зачисление проведено. Ответ содержит идентификатор проводки, счёт, сумму и время зачисления. |
| `CLOSED` | Проводки по идентификатору нет. Дальнейшее исполнение заблокировано. |

Если согласованное состояние временно невозможно подтвердить, АБС возвращает `409 READ_CONFLICT` с `instruction_id` и без бизнес-состояния. Сохранённый терминальный итог возвращается как `POSTED` или `CLOSED`. При совпадении идентификатора LoanFlow фиксирует исход чтения `CONFLICT`. Для новой команды закрытия нужно новое разрешающее чтение. При несовпадении идентификатора LoanFlow фиксирует `CORRELATION_ERROR`.

## Окончательное закрытие

АБС может закрыть `instruction_id` до получения исходного распоряжения. Закрытие и проведение зачисления взаимоисключающие, в том числе для распоряжений, уже принятых в очередь.

- Если зачисление проведено первым, АБС возвращает `POSTED` с данными проводки.
- Если закрытие зафиксировано первым, АБС сохраняет `CLOSED` и блокирует исполнение распоряжения, в том числе при его поздней доставке.

После потери ответа окончательный результат можно получить повторным закрытием или чтением по тому же идентификатору. Учебная АБС хранит терминальные записи `POSTED` и `CLOSED` бессрочно.

## Формат и корреляция { #abs-correlation }

Учебное распоряжение содержит `instruction_id`, `account_ref` для счёта клиента, целую сумму в копейках `amount_minor` и валюту `RUB`. Каждый ответ протокола отправки, чтения или закрытия возвращает `instruction_id`, включая `NOT_FOUND` и конфликт реквизитов. Ответ `POSTED` дополнительно возвращает идентификатор проводки, `account_ref`, `amount_minor`, валюту и время зачисления. При `CLOSED` реквизиты проводки отсутствуют.

LoanFlow сверяет идентификатор ответа с исходным запросом и сохранённым распоряжением. Для `POSTED` он также сверяет счёт, сумму и валюту. Некорректный ответ оставляет выдачу в обработке и резерв удержанным. Правила хранения и восстановления сверки описаны в [логической ER-модели](../04-data/2.1-logical-er-model.md#reconciliation-correlation).
