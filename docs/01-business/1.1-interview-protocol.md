# Протокол интервью с Бизнес-заказчиком (Начальник управления розничного кредитования)

**Дата:** 25 октября 2026 г.
**Проект:** LoanFlow (Кредитный конвейер)
**Тема:** Сбор бизнес-требований и определение границ MVP

## 1. Контекст и проблематика (AS-IS)
Текущая система (legacy-коробка) устарела и не продлевается после 2027 года.
- **Vendor-lock и Time-to-Market:** Изменения кредитной политики (лимиты, стоп-факторы) занимают 2–3 месяца и требуют оплаты подрядчику. Банк не успевает за требованиями ЦБ по ПДН, теряя деньги.
- **Низкая скорость:** Медиана автоодобрения — 40 минут (против минут у конкурентов). Ручной разбор занимает 1–2 дня.
- **Костыли регуляторики:** Период охлаждения и самозапрет реализованы поверх старой системы с долей ручного труда, что несет комплаенс-риски (штрафы ЦБ).
- **Рассинхрон каналов:** Отделения и мобильное приложение живут в разных системах. Возможны двойные заявки и разные решения по одному клиенту.

## 2. Целевые метрики и ограничения (TO-BE)
Дедлайн запуска MVP (жесткий): **1 июля 2027 года**.

| Метрика | Текущее значение (AS-IS) | Цель проекта (TO-BE) |
| :--- | :--- | :--- |
| Доля автоматических решений | ~55% | 80% (через год после MVP), далее 85%+ |
| Время до авто-решения | ~40 мин | < 3 мин для 90% заявок |
| Время до решения (ручное) | 1–2 рабочих дня | В тот же рабочий день |
| Конверсия (заявка → выдача) | ~18% | 25% |
| Уровень одобрения | Текущий | Не ниже текущего |
| Просрочка 30+ на 3-м месяце | ~2.4% | Не хуже текущей |
| Time-to-Market изменений политик | 2–3 месяца | < 2 недель |

*Примечание: Время до решения считается от нажатия кнопки «Отправить» до отображения статуса клиенту. Время ожидания в «период охлаждения» не учитывается в этой метрике.*

## 3. Границы MVP (Scope)
- **Продукт:** Кредит наличными без залога. Выдача только на счета/карты внутри банка.
- **Клиентопоток:** Только действующие клиенты (зарплатные проекты, держатели карт банка).
- **Каналы:** 
  - **Мобильное приложение (МП):** Основной канал выдачи.
  - **Отделения:** Только Read-Only режим. Сотрудник должен видеть статус, период охлаждения, сроки ответа.
  - **Интернет-банк:** На паузе. Зависит от оценки трудозатрат.

## 4. Бизнес-требования к процессу
- **Самозапрет:** Проверки каскадные — сначала внутренние бесплатные, затем дешёвые проверки самозапрета в БКИ, затем полные платные отчёты. При отказе из-за самозапрета клиенту выводится явный текст с рекомендацией снять его на Госуслугах.
- **Период охлаждения (4 ч / 48 ч):** Зачисление денег происходит автоматически по истечении таймера (без нажатия дополнительных кнопок клиентом). В UI отображается точное время зачисления. Кнопка «Отказаться» доступна всегда. Коммуникация только через Push, звонки запрещены.
- **Ручной андеррайтинг:** Новое единое рабочее окно для андеррайтера. Обязателен сбор статистики (скорость, % одобрений, последующая просрочка). На MVP выводится пилотная группа 15–20 человек.
- **Офисы:** Запрет на использование отдельного логина (требуется SSO/бесшовная интеграция). Причины отказа и скоринговый балл сотрудникам не выводятся.

- [ ] **Аналитик -> ИТ Интернет-банка:** Оценить трудозатраты на подключение ИБ к единому API. Если больше 1 месяца — перенос во второй релиз. Дедлайн принятия решения: конец ноября.
- [ ] **Аналитик -> Архитектура/Фронт-офис:** Проработать 2 варианта вывода статусов заявок для сотрудников отделений (SSO, интеграция) с оценкой сроков.
- [ ] **Аналитик -> Юристы:** Получить письменное подтверждение легитимности автоматического зачисления средств после периода охлаждения без доп. действий клиента.
- [ ] **Аналитик -> Юристы + Риски:** Определить процесс, если в течение 48 часов ожидания у клиента меняются данные (поставил самозапрет, вышла просрочка). Нужны ли повторные проверки перед автозачислением.
- [ ] **Аналитик -> Риски / Закупки:** Уточнить наличие и стоимость облегченных запросов проверки самозапрета в БКИ.
